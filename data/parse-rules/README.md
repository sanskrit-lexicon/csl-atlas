# Per-dictionary parse-rules (MUDIDI Pass-1 shape)

Deterministic, source-linked **parse-rules** for the CDSL dictionaries, in the shape
the [MUDIDI](https://github.com/DavidSamuell/MUDIDI) benchmark infers once per
dictionary before parsing pages into SIL's MDF schema. See the framing note
[`docs/PARSE_RULES_FRAMING.md`](../../docs/PARSE_RULES_FRAMING.md) and the candidate
[MDF export profile](https://github.com/sanskrit-lexicon/csl-standards/blob/main/docs/MDF_EXPORT_MAPPING.md).

Generated by [`scripts/parse_rules/build_parse_rules.py`](../../scripts/parse_rules/build_parse_rules.py)
from `../csl-orig/v02/<src>/<src>.txt` (source of truth) plus
`data/lexico/microstructure_fingerprint.json` (optional enrichment). No LLM inference.

```bash
python scripts/parse_rules/build_parse_rules.py
```

## What each `<dict>.json` contains

A MUDIDI Pass-1 parse-rules object has three parts; this artifact emits all three:

1. **`field_inventory`** — every CDSL markup tag the dictionary actually uses, with its
   count and its MDF target (`mdf`, `adequacy`, `role`) from the
   [MDF_EXPORT_MAPPING](https://github.com/sanskrit-lexicon/csl-standards/blob/main/docs/MDF_EXPORT_MAPPING.md)
   table. Tags with no MDF home are listed under `unmapped_tags` (surfaced, not dropped).
2. **`abbreviations`** — the abbreviation / siglum key: distinct `<ab>` abbreviations and
   distinct `<ls>` source sigla, each with a top-40 frequency list.
3. **`entry_structure`** — record/headword/homonym/sense/continuation markers and the
   dominant microstructure layer.

`evidence` labels every field as `observed` (counts), `derived` (MDF map, dominant
layer), per the atlas's evidence-label discipline.

## Coverage (v0.1)

11 dictionaries: mw, pwg, pwk (`pw`), ap, wil, ben, cae, skd, vcp, armh, abch.
See `index.json` for the summary table and `_validation.json` for per-dict status.

## Reading caveats — important

- **Zero is not absence.** SKD, VCP, ARMH, and ABCH carry almost no Western markup, so
  their `field_inventory` is near-empty *by construction* — they encode citations and
  verbs in indigenous prose (`iti`+authority, quotes, `dhātuḥ`/`preraṇe`/class names),
  not European tags. Each carries a `caveats` entry saying so. A 0 here is detector
  blindness, never a statement about content. See
  [`docs/MICROSTRUCTURE_ZERO_MEANING.md`](../../docs/MICROSTRUCTURE_ZERO_MEANING.md).
- **`ls_siglum_distinct` over-counts sources.** MW `<ls>` content includes coordinates
  (`RV. v, 86, 5`), so distinct counts are inflated; the real source key is the
  high-frequency head of `ls_siglum_top` (e.g. MW `L.` 40,212, `MBh.` 22,990, `RV.`).
- **Expansions are not yet linked.** The abbreviation *values* are listed; mapping them
  to expansions (`RV. → Ṛgveda`) needs the per-dict `abbr.html` / intro pages
  (e.g. `MWS/mwabbreviations/abbr.html`) and is a follow-up.

## Status

`schema: mudidi-parse-rules/0.1`. A by-product artifact, not yet wired to an atlas page
or to an MDF serializer. Intended uses: (1) feed a future `export-mdf` serializer in
`csl-standards`; (2) a Sanskrit contribution to the MUDIDI dataset, whose parsing subset
omits Sanskrit.
