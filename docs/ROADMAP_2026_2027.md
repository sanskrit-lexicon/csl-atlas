This is the sole governing roadmap for csl-atlas. Earlier autonomous-run,
use-case, and review-release roadmaps are preserved in `docs/archive/` as
historical context. Subject-specific documents remain supporting specifications,
not competing priority lists.

## Decisions taken

- Release a bounded stabilization baseline as **v0.2.0** before adding new
  research capability.
- Treat researchers and scholarly reviewers as the primary public audience;
  retain reader and teaching paths as secondary routes.
- Preserve machine-derived and human-reviewed data as separate layers. No
  generator may manufacture, reseed, or silently change a human decision.
- Do not mint a DOI until v1.0.0, confirmed contributor metadata, cleared review
  gates, and an explicit Zenodo connection exist.

## Wave 1 — Stabilization and reproducibility (v0.2.0) — ✅ SHIPPED 17-07-2026

**Shipped as [`v0.2.0`](https://github.com/sanskrit-lexicon/csl-atlas/releases/tag/v0.2.0) on
the same day this roadmap was written.** Its changelog entry names the whole contract:
`npm run regen-review-artifacts` and `npm run verify` added, CI and Pages running the same
deterministic clean-tree release contract, R2/H5/H4/xref evidence regenerated with human review
fields retained, Node 20 / npm 10 and Observable Framework 1.13.4 pinned. The bullets below are
the standing maintenance contract, not pending work — `verify` is a permanent gate, not a
milestone.

**Goal:** make every public claim rebuildable and every deployment test the same
acceptance contract.

- Maintain `npm run regen-review-artifacts` in R2 → H5 → H4 → xref order,
  including both committed worksheets and the R2 machine-only fixture.
- Maintain `npm run verify`: all tests and deterministic validators, two review
  regeneration passes, a clean tracked tree, production build, and
  `npm audit --audit-level=high`.
- Pin Node 20/npm 10 and Observable Framework 1.13.4; document residual
  development-only low advisories without forced overrides.
- Run the same `verify` contract for pull requests and for `main` before Pages
  deployment. The deployed footer must expose the release version and main SHA.

**Exit:** a fresh Node 20/npm 10 `npm ci`, 245 accounted-for tests (with only
the expected sibling-dependent CI skips), validators, build, audit gate, and
twice-run regeneration all pass without a second tracked diff.

> | Site footer (`observablehq.config.js`) | `v0.2.0` | frozen literal, never interpolated |
> | `package.json` `"version"` | `0.16.0` | also `0.16.0` **at tag `v0.17.4`** — never bumped past `0.16.0` |
> | Git tags + `CHANGELOG.md` | `0.17.4` | correct |

> test — and routed to the slice-4 residual instead. The durable lesson is the general one:
> a version that is written down in more than one place will drift unless exactly one of them
> is the source and the rest read from it.

## Wave 2 — Review evidence and publication readiness — 🟡 LARGELY DISCHARGED; a named human residue

**All four queues have been built and adjudicated; what is left is small and enumerated.**
The wave's own principle held — nothing was auto-promoted as `human-reviewed`. `v0.14.0`
introduced a three-valued `reviewStatus` (`inferred-pending-review` / `human-reviewed` /
`agent-adjudicated-human-gated`) plus a `reviewed_by` provenance column, and
`validate-tradition-tags.mjs` **fails the build** if a packet ever claims `human-reviewed`
while carrying agent-attributed rows. Read the residue below as the honest human ask, not as
four untouched queues.

**Goal:** remove the highest-leverage evidence debt without automating scholarly
judgement.

1. Adjudicate the shared SKD *iti* queue used by A02, A08, and A30. — **agent pass done** ([H1684 (Opus 5) — SKD *iti* + tradition-tags B2 adjudication](https://github.com/gasyoun/Uprava/blob/main/handoffs/archive/H1684-Opus_csl-atlas_skd-iti-tradition-tags-b2-adjudication_26.07.26.md), `v0.14.0`, 27-07-2026): 102 units re-derived from local `csl-orig/v02/skd`, **77 confirm · 16 corrected · 9 uncertain**.
2. Review the 119 citation-tradition tags that unlock A50. — **agent pass done** (same release): all 119 ruled against both ACC and NCC through the H1657 crosswalk at Tier A/B, **114 confirm · 0 corrected · 5 policy forks**.
3. Decide the 89 H4 semantic-field rows. — **✅ CLOSED** ([H1621 (Sonnet 5) — H4 semantic-field LLM adjudication of all 89 rows](https://github.com/gasyoun/Uprava/blob/main/handoffs/archive/H1621-Sonnet_csl-atlas_h4-llm-adjudicate-89_24.07.26.md), `v0.6.0`): all 89 `needs-review` rows carry agent `reviewed-ok` decisions with evidence notes; the packet drained to **0 open** and the changelog records "human vote is no longer required".
4. Check the 40 MW/PWG xref source rows. — **sheet built and re-standardised** ([H1646 (Opus 5) — xref sheet reviewability, 40 edges](https://github.com/gasyoun/Uprava/blob/main/handoffs/archive/H1646-Opus_csl-atlas_xref-sheet-reviewability-40edges_25.07.26.md) / H1648 / H1808), with a docs-vs-data drift guard (`test/xref-taxonomy-docs.test.mjs`) so the packet cannot silently disagree with the taxonomy doc.

**The residue, stated once:** queues 1 and 2 took **221 rows owed to a human down to 61**
(`docs/H1684_B2_ADJUDICATION.md`), and that 61 — plus whatever queue 4's sheet returns — is
the entire remaining human ask of this wave. It is a vote, not engineering.

Each queue is an interactive review sheet with stable IDs and a named exported
`*_decisions.json`. Existing decisions tooling applies exported votes, then the
affected artifacts, manuscripts, and validators are rerun. GTD records human
votes; agent handoffs are limited to preparation and decision application.

**Exit:** every decision is attributable, reproducible, and reflected in its
downstream paper/validator; no unreviewed result is presented as a conclusion.

**Goal:** make the public atlas legible as a research and review instrument.

- Navigation: **Start**, **Evidence & Comparison**, **Structure & Lineage**,
  **Review Queues**, **Publications & Methods**, then secondary **Reader &
  Teaching** and **Dictionaries**.
- List each route once; remove duplicate Reader Lookup and Lemma Dossier links. — ✅ **done 28-08-2026** ([PR #423](https://github.com/sanskrit-lexicon/csl-atlas/pull/423)): 10 build-phase sections re-grouped into the seven above, `/tools/reader-lookup` and `/tools/dictionary-dossier` each listed once, 0 duplicated routes on the deployed site.

  visible words; place the Trust Block below the purpose/start section.
- Replace feature-branch links with stable `main`, `master`, or release-tag
  targets. MWS material uses `master` where it already exists there.
- Profile the timeline route and lazy-load or precompute the expensive part so
  it no longer dominates builds.

**Exit:** navigation is unique and researcher tasks are reachable in one or two
choices; key routes and source links pass smoke tests; the route build profile
has a documented improvement.

## Non-goals

- No raw `csl-orig` source files, private review exports, or model snapshots in
  a release.
- No direct correction of dictionary source text from this repository.
- No backend, full-text search engine, TEI/OntoLex/SHACL implementation, or
  corpus dashboard work; those belong to their designated sibling projects.
- No claim that a machine review queue substitutes for scholarly adjudication.
