# R2 Checkpoint Decisions

Date: 2026-06-06

Status: empty decision-capture guide for the generated R2 checkpoint review
report. This is not parser promotion, not a public R2 page update, and not a
scholar-reviewed sense decision layer.

## Trust Block

- Claim: R2 checkpoint decisions are recorded as a shared atlas review-report
  overlay before any parser behavior changes.
- Evidence label: `derived`.
- Source file: `data/lexico/r2_checkpoint_review_packet.json`.
- Generated report: `src/data/review/r2-checkpoint-review.json`.
- Generated by: `npm run build-r2-checkpoint-review`.
- Review status: `needs-review`.
- Boundary note: dictionary source rows, existing R2 source anchors, recovered
  archive fixtures, and machine label proposals only.
- Archive parity policy: comparison/control signal only, not the optimization
  target.

## How To Review

Use [`R2_CHECKPOINT_REVIEW.md`](R2_CHECKPOINT_REVIEW.md) for the source-linked
worksheet and edit only the matching item in
`src/data/review/r2-checkpoint-review.json`.

For an unresolved row, keep:

```json
{
  "reviewStatus": "needs-review",
  "reviewedValue": null,
  "reviewer": null,
  "reviewedAt": null,
  "note": ""
}
```

When a human reviewer acts, set `reviewStatus` to `reviewed-ok`,
`reviewed-corrected`, `deferred`, or `blocked`, then fill `reviewer`,
`reviewedAt`, and `note`.

Use this `reviewedValue` shape when a parser-scope decision exists:

```json
{
  "acceptedParserLabels": ["target-primary-series"],
  "parserDisposition": "promote-parser-candidate"
}
```

Allowed `parserDisposition` values:

| Value | Meaning |
|---|---|
| `promote-parser-candidate` | The accepted labels can move toward a later parser experiment. |
| `retain-side-evidence` | Keep the row visible as evidence, but do not count it in the target parser window yet. |
| `control-only` | Use the row as a regression or archive-parity control, not a parser blocker. |
| `defer` | Valid row, but postpone the decision to a later R2 pass. |
| `block` | Cannot decide from current evidence. |

## Preservation Rule

`npm run build-r2-checkpoint-review` refreshes machine fields from the checkpoint
packet and preserves only human fields keyed by `reviewId`: `reviewStatus`,
`reviewedValue`, `reviewer`, `reviewedAt`, and `note`.

The stable `reviewId` for each row is its `diagnosticId`, for example
`r2-drift:gam:pwg`.

## Limits

- No checkpoint decision in this report changes R2 splitter behavior by itself.
- Do not edit `data/lexico/r2_checkpoint_review_packet.json` to record human
  decisions.
- Do not treat proposed parser labels as accepted sense decisions.
- Do not optimize rows to match archive counts; use archive parity only as a
  comparison/control signal.
