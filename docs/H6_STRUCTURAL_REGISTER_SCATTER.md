# H6 Structural-Register Scatter

Date: 2026-06-04

Status: implemented chart specification and trust block. The public atlas page
is `/tools/structural-register`, generated from
`src/data/dicts/structural-register.json`.

## Chart Trust Block

- Claim: structural register predicts dictionary family.
- Evidence label: `derived`, with interpretation currently
  `machine-reviewed`.
- Source files: `data/dictionary-coverage.json` and
  `data/lexico/microstructure_fingerprint.json`.
- Generated by: `npm run build-structural-register`; no backend.
- Validation: chart inputs must pass the relevant lexico validation commands and
  include row counts.
- Known false positives: dictionaries with sparse specialized content may look
  structurally distinctive because their genre is narrow.
- Known false negatives: indigenous citation and grammar conventions can be
  undercounted if only Western tags are used.
- Review status: chart interpretation needs scholar review before paper use.
- Owner repo: `csl-atlas`.
- External dependencies: none for v1; VisualDCS, standards, and observatory data
  are out of scope.
- Boundary note: this chart uses dictionary structure only, not corpus passages
  or GitHub/org activity.

## Page Purpose

The page shows whether citation style and grammar-marking separate
dictionary families:

- Western-tagged citation apparatus;
- indigenous quotation and grammatical prose;
- index/catalogue traditions;
- specialized dictionaries with narrow structural signatures.

It is a scholar-facing page first. Public reader language can come later.

## Implemented Minimal Chart

| Axis | Meaning | Data source |
|---|---|---|
| x | citation-register share | `dictionary-coverage.json` `blockPct.citeTagged` and `blockPct.citeInlineIti` |
| y | grammar-marking share | `dictionary-coverage.json` `blockPct.gram` |

## Chart Input Contract

The build emits `src/data/dicts/structural-register.json`, with one row per
dictionary.

| Field | Type | Source | Meaning |
|---|---|---|---|
| `code` | string | `dictionary-coverage.json` `code` | Display dictionary code, e.g. `MW`, `PWG`, `SKD`. |
| `sourceCode` | string | `dictionary-coverage.json` `sourceCode` | Lowercase source code used for joins, e.g. `mw`, `pwg`, `skd`. |
| `title` | string | `dictionary-coverage.json` `title` | Human-readable dictionary title. |
| `records` | number | `dictionary-coverage.json` `records` | Entry count; use for point size only after square-root or log scaling. |
| `grammarPct` | number | `dictionary-coverage.json` `blockPct.gram` | Share of records with visible grammar marking. |
| `taggedCitationPct` | number | `dictionary-coverage.json` `blockPct.citeTagged` | Share of records with `<ls>` citation tags. |
| `inlineItiPct` | number | `dictionary-coverage.json` `blockPct.citeInlineIti` | Share of records with `iti`-style prose citation evidence. |
| `citationRegisterPct` | number | derived | `max(taggedCitationPct, inlineItiPct)` for the x-axis. |
| `citationRegisterMode` | enum | derived | `tagged`, `iti`, `mixed`, or `low`. |
| `fitBand` | string | `dictionary-coverage.json` `fitBand` | Existing structural fit label. |
| `fitScore` | number | `dictionary-coverage.json` `fitScore` | Existing coverage/structure score. |
| `dominantLayer` | string | `microstructure_fingerprint.json` `dominant_layer` | Dominant M1-M5 layer: `subentry`, `preverb`, `xref`, `root`, or empty. |
| `subentryPer1k` | number | `microstructure_fingerprint.json` `subentry.per_1k_entries` | Subentry density, useful in tooltip. |
| `xrefEdges` | number | `microstructure_fingerprint.json` `xref.edges` | Cross-reference edge count, useful in tooltip. |
| `rootEntries` | number | `microstructure_fingerprint.json` `root.entries` | Indigenous/root-layer count, useful in tooltip. |
| `familyLabel` | enum | curated | Scholar-facing family/tradition label. |
| `warnings` | string[] | derived/curated | Convention caveats to show in tooltip or side note. |

## Derived Fields

`citationRegisterMode` should be computed conservatively:

| Rule | Mode |
|---|---|
| `taggedCitationPct >= 5` and `inlineItiPct < 5` | `tagged` |
| `inlineItiPct >= 5` and `taggedCitationPct < 5` | `iti` |
| both are `>= 5` | `mixed` |
| both are `< 5` | `low` |

`citationRegisterPct = max(taggedCitationPct, inlineItiPct)` is a practical
x-axis for the first scatter. Tooltips must still show both raw components so
an indigenous `iti` signal is not confused with Western `<ls>` tagging.

## Family Labels

Use family labels as interpretation aids, not as proof. A first curated mapping
can use these buckets:

| Label | Typical dictionaries | Interpretation |
|---|---|---|
| `western-tagged` | MW, AP, PWG, PW/PWK, BEN, CAE, BHS, STC | European-style tagged or semi-tagged apparatus. |
| `indigenous-prose` | SKD, VCP, KRM | Sanskrit-Sanskrit or root-list conventions; prose and indigenous grammar matter. |
| `index-catalogue` | ACC, IEG, INM, MCI, SNP, VEI | Reference/index genre; structure is not the same as a narrative dictionary. |
| `reverse-bilingual` | AE, APTEES, MWE if present | English-to-Sanskrit lookup genre; sense direction differs. |
| `specialized` | botanical, name, epigraphic, Buddhist, or narrow-domain dictionaries when not already covered | Narrow genre can create structural outliers. |
| `unknown` | any unassigned source | Do not infer family from absence of curation. |

The chart may later compare these labels with the L0 genealogy tree, but the
scatter itself does not prove descent.

## Build Plan

Implemented by `scripts/build-structural-register.mjs`; keep this plan as the
maintenance contract for future changes.

1. Read `data/dictionary-coverage.json`.
2. Read `data/lexico/microstructure_fingerprint.json`.
3. Join by `sourceCode` from coverage to the lowercase key in
   `microstructure_fingerprint.json`.
4. Compute `citationRegisterPct`, `citationRegisterMode`, `familyLabel`, and
   `warnings`.
5. Emit a static JSON file under `src/data/dicts/`.
6. Render a static Observable scatter from the emitted JSON.

No corpus, DCS, TEI/OntoLex, FrAC, GitHub, or organization metrics are inputs.

## Warning Rules

| Condition | Warning |
|---|---|
| `taggedCitationPct < 1` and `inlineItiPct >= 5` | "Citation evidence is prose/iti, not `<ls>`." |
| `grammarPct < 5` and `dominantLayer == "root"` | "Grammar may live in indigenous root/prose conventions." |
| `records < 1000` | "Small specialized source; structural percentages may be unstable." |
| `familyLabel == "index-catalogue"` | "Index/catalogue genre; compare cautiously with narrative dictionaries." |
| `dominantLayer == ""` | "No M1-M5 microstructure layer detected; this may be a convention gap." |

## Visual Encoding

| Channel | Encoding | Reason |
|---|---|---|
| x | `citationRegisterPct` | Separates citation-heavy and citation-light registers. |
| y | `grammarPct` | Separates grammar-marked and grammar-light registers. |
| color | `familyLabel` | Tests whether known traditions cluster. |
| shape | `citationRegisterMode` or `dominantLayer` | Shows whether the citation signal is tagged, prose, mixed, or low. |
| size | square-root scaled `records` | Gives corpus scale without letting MW dominate visually. |
| tooltip | raw fields and warnings | Keeps uncertainty visible. |

Use a log or square-root scale for point size. Do not use raw record count as
area without scaling.

## Interpretation Guide

The expected reading is:

- upper-right tagged cluster: dictionaries with visible grammar and citation
  apparatus;
- upper-right or right-side prose cluster: indigenous dictionaries when `iti`
  citation is counted;
- lower-right or shape-specific points: source-heavy indexes or catalogues;
- lower-left points: dictionaries where the current detectors see little of the
  chosen structure, not necessarily content-poor dictionaries.

This page should use language such as "structural similarity" and "register
family." Avoid "descent" unless a separate lineage test supports it.

| Check | Expected |
|---|---|

| every row has `code`, `sourceCode`, `records`, `grammarPct`, `citationRegisterPct` | yes |

| `familyLabel` is one of the curated labels above | yes |
| no external repo data required | yes |
| every warning is deterministic or curated in the generator | yes |

Recommended validation commands:

```sh
python scripts/lexico/validate_lexico.py
```

Then render `src/tools/structural-register.md` from the emitted JSON.
